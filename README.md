# kancolle-SAFARI — Safety v2.5.3

iPhone / iPad Safari + Userscripts、および Chrome + Tampermonkey 向けの非公式・受動型プレイ補助ツールです。

## 重要事項

**本ツールが利用規約に抵触しないことを保証するものではありません。** 利用前に最新のDMM/艦これの規約・告知を確認してください。

v2.5.3はリスクを最小化するため、ゲームサーバーへの追加リクエスト、API再送、通信改変、自動操作、マクロ、BOTを設計上禁止しています。ゲーム本体が通常操作で受信したレスポンスだけを受動観測します。Cookie、ログイン情報、request body、`api_token` は保存・出力しません。

リクエスト側から読むのは、レスポンスだけでは識別できない以下の**非機密な数値フィールドだけ**です。request bodyそのものは保存しません。

- 出撃開始: `api_deck_id`, `api_maparea_id`, `api_mapinfo_no`, `api_formation_id`
- 任務一覧: `api_page_no`, `api_tab_id`
- 基地航空隊: `api_area_id`

## 現行ファイル — この2本だけ

Safari / Userscripts と Chrome / Tampermonkey で **同じ2ファイル** を使います。

1. `kancolle-page-bridge.user.js` — 通常通信の受動観測
2. `kancolle-safety.user.js` — Safety UI、大破ブロッカー、DB出力、スクリーンショット

`.chrome.user.js` の複製ラッパーは廃止しています。ルートにある上記2本が唯一の現行Userscriptです。

## v2.5.3で修正した点

- 任務APIの `api_tab_id` / `api_page_no` を機密情報と分離して受動取得
- 「全て」タブ (`api_tab_id=0`) の件数と取得件数が一致した場合に任務全件取得済みと判定
- 基地航空隊APIの `api_area_id` を保持し、複数方面の基地ID衝突を防止
- `goback_port`、母港帰投、新しい出撃開始で出撃ログを確実に確定
- 未対応の友軍側被ダメージフィールドを検出した場合は、安全側に倒して大破判定を「確認不能」にする
- 戦闘計算HPが0以下になった場合、ダメコン消費の有無を推測せず、次の艦データ受信まで赤警告/ブロック
- 噴式強襲相当の `api_injection_kouku` / `api_injection_kouku2` と第2航空戦 `api_kouku2` の友軍被ダメージを処理
- 戦闘結果でSafetyパネルを自動展開しない

## かんこれDB

ゲーム本体が通常操作で受信したデータだけをセッション内で収集します。対象はマスター、提督情報、艦娘、装備、艦隊、HP、Cond、資源、資材、アイテム、入渠、建造、遠征、任務、海域、基地航空隊、出撃ノード、戦闘結果などです。

追加APIを送らないため、未表示画面の情報をツール側から取りに行くことはありません。完全取得を狙う場合は通常操作で次を順番に表示してください。

`再読込 → 母港 → 編成 → 改装/装備 → 入渠 → 工廠 → 遠征 → 任務の「全て」タブ → 海域選択 → 基地航空隊がある各方面 → 必要なら通常出撃 → 母港 → 書き出し`

### 完全性の考え方

- **任務:** 「全て」タブのレスポンス件数と取得件数が一致すれば `任務全件` を✅にします。
- **基地航空隊:** 通常操作で受信した基地だけを保存します。ツールから未表示方面を取得しに行きません。各基地は方面IDと基地IDの組で保存します。
- **出撃ログ:** 出撃開始からノード/戦闘を蓄積し、母港帰投・`goback_port`・次の出撃開始時に履歴へ確定します。
- **戦闘HP:** 対応済みフェーズだけで計算します。未知の友軍被ダメージ構造を検出した場合は推測せず赤ブロックします。
- **ダメコン:** 発動の可能性があるHP0以下の計算結果では、装備が残っていると仮定しません。サーバーから艦データを再受信するまで確認不能扱いです。

## iPhone / iPad

1. App StoreからUserscriptsをインストール
2. 設定 → アプリ → Safari → 機能拡張 → Userscriptsを有効化
3. 上記2ファイルをUserscriptsの保存フォルダへ保存
4. DMM / 艦これゲームサーバーでUserscriptsの実行を許可
5. 艦これを完全に再読み込み
6. 右上に `⚓ 待機` が表示されればUI起動成功

## Chrome

Tampermonkeyへ **同じ2ファイルの内容をそれぞれ登録**して有効化し、艦これを完全に再読み込みしてください。Chrome/Tampermonkey側でユーザースクリプト実行許可が必要な環境では、その設定も有効にしてください。

## 安全性CI

`scripts/safety-audit.mjs` と `.github/workflows/safety-audit.yml` で以下を静的チェックします。

- Bridgeが新規XHRを作らない
- `GM_xmlhttpRequest` を使わない
- Cookie APIを使わない
- request bodyから `api_token` を読まない
- request metadataは任務/基地/出撃のallowlistだけ
- Bridgeにクリック自動化がない
- ゲーム本体のXHR/fetchを各1回だけpass-throughする
- UI側がネットワークリクエストを発行しない
- 任務全件判定・基地方面保持・出撃確定処理が存在する
- 未対応ダメージフェーズとダメコン発動可能性をfail-closedで扱う
- JavaScript構文チェック

API仕様変更やデータ不足で大破/ダメコンを確実に判定できない場合は、安全側に倒して赤警告/ブロックします。

CIは技術的な実装ミスを検出するためのもので、利用規約上の許可を保証するものではありません。このツールは非公式です。
