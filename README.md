# kancolle-SAFARI

iPhone / iPad Safari 向けの、艦これプレイ補助用ユーザースクリプトです。

> **v0.1 は実機検証前の試作版です。イベント本番へ持ち込む前に、通常海域などで必ず大破警告と進撃ガードの位置を確認してください。**

## v0.1 の機能

- 艦これ本体が受信した `kcsapi` の内容を読み取る
- 艦隊状態タブ
  - 艦名 / Lv
  - HP
  - 大破・中破・小破判定
  - 燃料
  - 弾薬
  - 搭載数（スロットごと）
  - 連合艦隊の第1 / 第2艦隊切替
- 戦闘後HPを戦闘APIから計算して更新
- 戦闘結果後、状態タブを自動で開く
- 大破時の画面警告
- 大破時の「進撃」誤タップ防止ガード
  - 通常タップをブロック
  - ガードを約2.4秒以内に3連続タップすると5秒だけ解除
  - 解除後も進撃は自動では行わず、本物の「進撃」をユーザー自身で押す
- Web Notification API が利用できる環境では通知テスト / 大破通知
- 対応環境では振動

## 大事な表示上の注意

### HP

`*` が付いたHPは、戦闘APIから各戦闘フェーズの被ダメージを計算した **戦闘後計算値** です。

連合艦隊では `api_f_nowhps` と `api_f_nowhps_combined` を連結して第1・第2艦隊を扱います。

未知の戦闘形式などでHPを安全に判定できない場合は「判定不明」とし、安全側で進撃ロックを出す設計です。

### 燃料・弾薬

v0.1 では **最後にAPIから直接取得できた値** を表示します。戦闘ごとの消費を推定して「現在値」と偽装することはしていません。

### 搭載数

各艦の `api_onslot` の **最後に取得できた値** を表示します。

航空戦APIから取得できる総搭載数 / 総損失数も表示しますが、総損失を各スロットへ勝手に按分しません。そのため、戦闘直後の各スロット残機数とは一致しない場合があります。

## iPhone / iPad での導入（Userscripts）

1. App Store から **Userscripts** をインストール
2. iPhone の「設定」→「アプリ」→「Safari」→「機能拡張」で Userscripts を有効化
3. Userscripts のスクリプト保存フォルダへ `kancolle-safety.user.js` を保存
4. Safari で艦これを開く
5. Safari の機能拡張設定で、艦これ / DMM / ゲームサーバー上で Userscripts の実行を許可
6. 母港を一度表示する
7. 画面右上に **⚓ 状態** が出ればAPI取得成功

## 最初に行うテスト

1. 通常海域へ安全な艦隊で出撃
2. 戦闘後に「⚓ 状態」を開いてHP・燃料・弾薬・搭載数が表示されることを確認
3. 中破艦で中破判定が出ることを確認
4. **大破艦が出たとき、進撃/撤退画面の「進撃」上に赤いガードが重なることを確認**
5. ガードを1〜2回タップしても進撃できないことを確認
6. ガードを3連続タップすると5秒間だけ解除されることを確認
7. 撤退して母港へ戻る

### 進撃ガードの位置

艦これ第二期 1200x720 を基準に初期値を設定していますが、iPhoneの表示倍率やゲーム画面の配置によってずれる可能性があります。

`kancolle-safety.user.js` 冒頭の以下を調整できます。

```js
const GUARD = { x: 0.285, y: 0.585, w: 0.205, h: 0.17 };
```

- `x`: 左からの位置
- `y`: 上からの位置
- `w`: 幅
- `h`: 高さ

すべてゲーム画面サイズに対する比率です。

## iPhoneの通知について

通常のiPhone Safariでは、ページ上のJavaScriptからネイティブ通知を常に出せるわけではありません。

v0.1 は利用可能な場合だけ Web Notification API を使い、利用できない場合でも **画面上の赤い警告と進撃ガード** は独立して動く設計です。

確実なiPhoneネイティブ通知が必要なら、次段階で専用アプリまたはホーム画面Webアプリ(PWA)側に通知機能を持たせる予定です。

## 設計方針

- ゲームサーバーへ独自の操作リクエストを送らない
- APIレスポンスを書き換えない
- 自動出撃・自動進撃・自動撤退を行わない
- 進撃ガードは誤タップを防ぎ、解除もユーザーの明示操作だけで行う

このツールは非公式です。艦これ / DMM の仕様変更で動かなくなる可能性があります。

## Audit JSON 書き出し（受動監視のみ）

`kancolle-audit-export.user.js` を追加すると、Safety のパネル内に **「📦 完全JSON書き出し」** が表示されます。Safety が見つからない場合は、独立した `📦 Audit` ボタンが表示されます。

### 安全設計

- **艦これサーバーへ追加の HTTP / XHR / fetch リクエストを送信しません**
- ゲーム本体が通常操作で発行した通信の **レスポンスを受動的に読むだけ** です
- request body は読み取り・保存・転送しません
- `api_token` は保存しません
- APIレスポンスの改変、自動操作、自動巡回は行いません
- 取得データはページ内メモリに保持し、Safariを再読み込みすると消えます

### 導入

1. `kancolle-audit-export.user.js` を Userscripts の保存フォルダへ追加
2. DMM / 艦これゲームサーバーで Userscripts の実行を許可
3. **艦これのページを再読み込み**する（`api_start2/getData` を通常起動時に受動取得するため）
4. 母港や装備・任務・基地航空隊など、必要な画面をゲーム内で普通に開く
5. `⚓ 状態` → `📦 完全JSON書き出し` で取得状況を確認
6. `JSON書き出し` または `共有` を押す

出力名は `kancolle_final_audit_YYYYMMDD-HHMMSS.json` です。

### 取得漏れについて

追加リクエストを行わない設計のため、**ゲーム内でまだ表示していない画面のデータは未取得のまま**です。パネルに未取得項目を表示します。必要な画面を手動で開くと、その通常通信を受動取得します。

任務はページ分割されているため、完全な任務一覧が必要な場合は **任務画面を手動で各ページ表示**してください。スクリプト側から任務ページを自動巡回することはありません。
